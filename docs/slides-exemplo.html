model Cliente {
  id           Int      @id @default(autoincrement())
  nome         String   @db.VarChar(100)
  email        String   @unique @db.VarChar(100)
  cidade       String   @db.VarChar(50)
  dataCadastro DateTime @map("data_cadastro") @db.Date
  pedidos      Pedido[]

  @@map("clientes")
}

CREATE TABLE IF NOT EXISTS clientes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    cidade VARCHAR(50) NOT NULL,
    data_cadastro DATE NOT NULL
) ENGINE=InnoDB;

ORM não é mágica: Ganhos × Riscos

5 / 12
✓ Por que adotar um ORM
  • Tipagem forte: erros de coluna ou tipo aparecem no editor antes de rodar.
  • Produtividade no CRUD: menos código SQL repetitivo para consultas simples.
  • Segurança padrão: queries parametrizadas evitam SQL Injection.
! O que exige atenção
  • Abstração enganosa: o código fica limpo, mas esconde quantas queries vão ao banco.
  • Perda de controle fino: consultas analíticas complexas podem gerar SQL subótimo.
Gancho para o Pilar 2:
“E a armadilha mais famosa dessa abstração é o Problema N+1.”

Código “inocente”, explosão no MySQL

7 / 12
TypeScript — Loop com N+1 02-problema-n1.ts 
const pedidos = await prisma.pedido.findMany(); // 1 query

for (const p of pedidos) {
  const cli = await prisma.cliente.findUnique({ // +N queries!
    where: { id: p.clienteId },
  });
}
O que chega ao MySQL 36 round-trips 
-- [1] Busca a lista inicial
SELECT ... FROM pedidos;

-- [2..36] Uma query nova a cada volta do for
SELECT ... FROM clientes WHERE id = ?; -- (x35)
Medido no general_log
35 pedidos listados
36 queries
Inspeção ao vivo: o terminal liga o mysql.general_log, limpa a tabela e conta exatamente cada query que chegou no MySQL.

Eager Loading: include (IN) vs. join

8 / 12
📦
Analogia do Pedido Consolidado: em vez de 35 viagens, carregar todos os clientes necessários de forma antecipada antes do loop.
1. Padrão (query / IN) 2 queries 
await prisma.pedido.findMany({
  include: { cliente: true },
});
Vantagem: evita duplicar dados do registro pai na rede.
2. relationLoadStrategy: "join" 1 query 
await prisma.pedido.findMany({
  relationLoadStrategy: "join",
  include: { cliente: true },
});
Vantagem: menor latência (apenas 1 ida ao MySQL 8).
▶ DEMO AO VIVO — Opção 3 (include IN: 2 queries) e Opção 4 (join: 1 query) npm start → [3] e [4]

Enxugando colunas com select

9 / 12
Prisma com select aninhado 03-eager-loading.ts 
await prisma.pedido.findMany({
  select: {
    id: true,
    status: true,
    cliente: { select: { nome: true } },
    itens: {
      select: { quantidade: true, precoUnitario: true }
    }
  }
});
1. Evite “SELECT *” disfarçado
include carrega todas as colunas da tabela relacionada. Com select, trafega apenas o que a tela precisa.
2. Atenção ao N+1 em cascata
Em pedidos → itens → produtos, loops aninhados multiplicam queries exponencialmente. select/include aninhado resolve em lote!

Quando abandonar o ORM e ir de SQL Manual

10 / 12
🔐
Analogia: Acesso direto ao cofre / relatório gerencial — ir direto ao MySQL quando o atalho do ORM limita a consulta.
3 Critérios Objetivos
• Agregações: SUM(...) + GROUP BY  |  • Filtros diretos: LEFT JOIN ... IS NULL  |  • Tuning: relatórios pesados.
Ranking de Faturamento ($queryRaw) 04-sql-manual.ts 
// Top 10 Clientes por Faturamento (SUM + GROUP BY)
const ranking = await prisma.$queryRaw`
  SELECT c.nome AS cliente,
    COUNT(DISTINCT p.id) AS totalPedidos,
    SUM(ip.quantidade * ip.preco_unitario) AS totalGasto
  FROM clientes c
  INNER JOIN pedidos p ON p.cliente_id = c.id
  INNER JOIN itens_pedido ip ON ip.pedido_id = p.id
  WHERE p.status <> 'cancelado'
  GROUP BY c.id, c.nome
  ORDER BY totalGasto DESC LIMIT 10
`;
Clientes sem Compras ($queryRaw) 04-sql-manual.ts 
// Clientes que NUNCA compraram (LEFT JOIN)
const semPedidos = await prisma.$queryRaw`
  SELECT c.id, c.nome, c.email, c.cidade
  FROM clientes c
  LEFT JOIN pedidos p ON p.cliente_id = c.id
  WHERE p.id IS NULL
  ORDER BY c.id ASC
`;
Segurança: tagged template do $queryRaw parametriza variáveis contra SQL Injection.
